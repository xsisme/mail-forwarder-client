# 邮件转发助手 v1.3.2 · iOS 风格

把 POP3 邮箱的新邮件转发到企业微信群机器人或 QQ / SMTP 邮箱。所有原脚本的业务配置都可以在窗口中填写；Windows 支持加密记住密码，后续打开自动回填。

## 从旧版更新

v1.3.2 修复 Windows 打包前“发送阻塞取消”测试的时序问题：旧测试使用固定 8 MiB 数据，可能在请求停止前就已发送成功。新测试持续发送小块数据，确认真实发送已进入等待后才请求取消，仍要求 1.5 秒内停止，不跳过测试或降低取消时限。

先关闭旧客户端，把新压缩包中的 `MailForwarderClient` 文件夹内容覆盖到原项目目录，再运行 `build_windows.bat`。原有 Python 和构建环境可以继续使用，界面依赖会自动安装。已保存的账号配置、密码和邮件处理记录继续沿用。

v1.3.1 修复 Windows 构建时 6 个网络取消场景失败的问题：连接建立后，网络读写每隔约 0.2 秒检查停止请求，处理系统关闭连接后仍未唤醒等待的情况。短暂等待不会损坏分段到达的邮件或 HTTP 数据，实际网络超时仍使用界面配置。新增系统唤醒失效、慢速分段数据、原超时保留和发送阻塞的回归测试；原有测试与时间限制保留。

v1.3.0 加入关闭窗口收尾上限：点击停止 / 关闭会取消网络任务，关闭窗口最多给后台任务约 2 秒收尾时间，然后退出界面。DNS、建连或 TLS 握手等尚不能中断的系统调用不再无限阻止客户端退出。已确认投递的处理记录继续保存，旧版窗口初始化修复保留。

新增「运行策略 → 发件人排除名单」。名单中的邮箱来信不会转发到企业微信或 SMTP；排除规则优先于关键词，首次测试邮件和失败重试邮件同样生效。旧配置自动补充为空名单，保持原来的转发行为。公开源码不预填个人邮箱、公司服务器或凭据。

v1.2.0 修复窗口初始化时提前关闭引起的 `application has been destroyed`：关闭请求与异常退出会等 CustomTkinter 的 Windows 主循环初始化完成后再执行；普通启动测试也在初始化完成后检查、关闭窗口。该测试失败会输出并保留完整启动日志。

新增「提醒成员 UserID」，Markdown 使用 `<@UserID>` 提醒指定成员，text 使用成员列表；提醒标记放在 Markdown 正文前，长邮件截断时仍保留完整标记。另附 A、B 多开脚本，通过已有的 `--data-dir` 参数隔离实例，无需修改配置目录或锁机制。

v1.1.3 修复顶部检测区提示显示不全：取消原先超过 17 个字符就加省略号的限制，完整显示检测消息；状态文字按当前列宽自动换行，检测栏高度随内容调整。列宽计算考虑 CustomTkinter 的缩放，避免 Windows 放大字体后被固定高度裁切。

**如果旧版打开后窗口消失、任务管理器里仍有进程：**先在任务管理器「详细信息」中结束旧的 `MailForwarderClient.exe` 进程，再覆盖文件、重新打包，运行新生成的 `dist\MailForwarderClient.exe`。不要只运行之前复制到桌面的旧 EXE。无需删除配置、密码或处理记录。

v1.1.2 调整打包前的窗口自检：启动检查在独立进程运行，隔离前序测试创建和销毁多个 Tk 窗口留下的全局状态；在真实 Windows 上使用原生标题栏 API。可见性检查允许初次显示和重绘等待，随后要求窗口及按钮连续可见至少 2 秒，10 秒内达不到则失败。自检期间禁用输入并在标题中提示自动关闭，请勿操作检查窗口。

失败时直接输出 `startup.log` 的末尾内容；功能测试中的独立启动检查失败，还会把日志、结果和检查输出保留到项目目录下的 `.build-test-logs`，不随临时目录删除。构建成功会输出 EXE 的完整路径，并在资源管理器中选中生成的文件。

本版保留 v1.1.1 的窗口显示修复：不在进入主循环前主动隐藏窗口或调用 `update()`，避免与 CustomTkinter 的 Windows 标题栏初始化冲突。正常启动和离线检查使用相同的主循环路径；检查失败或超时会使构建失败，不能仅凭 EXE 返回码认定成功。

新增 `startup.log` 记录启动、窗口状态和异常堆栈；启动或界面回调异常会结束事件循环并释放单实例锁，显示日志位置。正常关闭窗口前取消待执行的 UI 回调。

v1.1.0 改为 iOS 风格桌面界面：浅色背景、圆角卡片、蓝色主操作、绿色开关、左侧导航，以及独立运行日志页。表单可滚动，开始和停止操作固定在底部；所有原有参数与功能保留。

继承 v1.0.1 修复：测试读取 UTF-8 文件时受 Windows 默认 GBK 编码影响的问题；修复中文计算机名使 SMTP 的 Message-ID / EHLO 编码失败的问题；处理本地模拟服务器正常探测断开时的 Windows 10053 / 10054；协议测试失败时会输出具体原因。构建前测试仍完整执行。

## 先运行，再生成 EXE

这个交付包是**完整客户端源码和 Windows 一键打包工具**，不包含已编译 EXE。构建一次后，生成的 EXE 可在不安装 Python 的 Windows 电脑上运行。

1. 在 Windows 10 / 11 电脑上安装 Python 3.10 或更高版本，建议使用 Python 3.11 / 3.12 的 python.org 标准安装包，勾选 `Add Python to PATH` 和 `tcl/tk and IDLE`。
2. 解压整个文件夹。双击 `run_windows.bat` 即可直接打开客户端；首次运行会自动安装 CustomTkinter 和 Pillow 界面依赖。
3. 双击 `build_windows.bat` 生成独立程序。首次打包需要联网安装 PyInstaller，脚本会创建独立构建环境，并先运行自动化测试、Windows 凭据加密测试及界面启动检查。生成 EXE 后会再次打开窗口，稳定显示至少两秒后自动关闭。请等待打包窗口显示 `SUCCESS`；之前弹出的检查窗口不表示已经生成 EXE。
4. 构建完成后，程序位于 `dist\MailForwarderClient.exe`。把这个 EXE 复制到需要运行的 Windows 电脑即可。`dist` 内同时生成 `start_account_A.bat`、`start_account_B.bat`，用于多开。

Python 安装地址：https://www.python.org/downloads/windows/

## 从 GitHub 下载自动构建的 Windows 程序

仓库包含 `Windows tests and EXE` 自动流程。提交到 `main`、提交 Pull Request，或在 Actions 页面手动运行时，会在 Windows 环境中执行完整测试和窗口启动检查；测试通过后再生成 EXE，并检查打包后的窗口能持续显示。

进入仓库的 **Actions → Windows tests and EXE**，打开一次成功的运行，在 **Artifacts** 下载 `MailForwarderClient-Windows`。解压后运行 `MailForwarderClient.exe`；A、B 多开脚本与 EXE 放在同一目录即可。构建产物保留 30 天，失败诊断日志保留 7 天。

自动流程覆盖 Python 3.11 / 3.12 的 Windows 测试，使用 Python 3.11 打包。构建使用干净环境，账号、密码和 Webhook 由使用者在自己的电脑上填写。测试失败时不会生成可下载的程序包。

## 首次使用

1. 确保能访问自己的邮箱服务器；内网邮箱按需连接 VPN。
2. 在「邮箱账户」填写 POP3 服务器、端口、加密方式、邮箱账号及密码 / 授权码。
3. 在「转发通道」勾选企业微信或 SMTP 邮箱，填入对应配置。QQ 邮箱的发信凭据是 SMTP 授权码；收件邮箱留空表示发给发件账号自己。本版每个 SMTP 通道支持一个收件地址。
4. 在「运行策略」设置检查间隔、网络超时、关键词过滤、发件人排除名单及首次测试策略。
5. 打开「邮箱账户」中的「记住登录信息」开关。点击「保存配置」，或直接点击「登录并检测」；检测和开始转发都会自动保存当前配置。
6. 点击「登录并检测」。它会检查 DNS / TCP、POP3 登录、邮箱 STAT / UIDL，并向已启用通道发送一条无真实邮件内容的测试通知 / 测试邮件。
7. 在群和收件邮箱确认收到测试消息后，点击「开始转发」。直接点击开始，也会先检测尚未验证的配置。

保存的配置会在下次启动时自动回填；不会自动连接或开始转发。首次打开需要输入自己的账号及凭据，交付包不包含原脚本内的密码、授权码或机器人密钥。

「仅检测邮箱」不发测试通知，也不要求填写转发通道配置。它不会建立邮件历史基线。

## Markdown @指定成员

在「转发通道 → 企业微信群 → 提醒成员 UserID」填入成员的企业微信账号，例如：

```text
zhangsan,lisi
```

支持逗号、中文逗号或换行分隔，前缀 `@` 可省略；同一账号去重，每次最多 20 个。Markdown 和 text 都能使用这项配置。Markdown 内容将带有 `<@zhangsan> <@lisi>`，普通的 `@张三` 显示文字不会自动转换成成员提醒。

请填写企微通讯录中的「账号 / UserID」。仅凭昵称、中文姓名或手机号，当前 Webhook 不能自动查找对应 UserID；可向企业微信管理员确认。程序校验格式，不验证成员是否真实存在或在目标群中。「登录并检测」发送的测试消息也会使用提醒配置，请在群里确认实际提醒效果。

「提醒手机号」仍仅对 text 生效；如需提醒全员，使用 text 并在该项填 `@all`。新 UserID 项用于指定具体成员。

## 不转发某些邮箱的来信

先点击「停止」，在「运行策略 → 发件人排除名单 → 排除发件邮箱」中填写完整邮箱，例如 `news@example.com, alerts@example.com`（仅示例）。点击「保存配置」，再「开始转发」。多个邮箱支持中英文逗号、分号或换行分隔；留空表示不排除。

- 按原邮件 `From` 中的完整邮箱匹配，忽略大小写。支持 `姓名 <邮箱>` 形式的发件人；显示姓名、正文中提到的邮箱和相似地址不会误触发。
- 排除规则对两个通道同时生效，优先于关键词和「首次测试最后一封邮件」。关键词留空时仍执行排除规则。
- 某邮件已在一个通道成功、另一个通道待重试时，加入名单会停止剩余投递；已经发出的消息无法撤回。
- 被排除的邮件会记入本地处理记录，并计入「过滤」数量。移除邮箱后不会补发这些历史邮件，仅允许后续新邮件按规则处理。
- 「登录并检测」发送的是客户端生成的通道测试通知，仍会正常发送。
- 当前按具体邮箱地址排除，不支持整个域名、通配符或收件人条件。多个账号各自保存独立名单。

## 同时运行多个账号

已有 `--data-dir` 参数可为每个实例指定独立的数据目录。只复制、改名 EXE 仍会使用同一个默认目录，不能因此绕过单实例锁。

打包后，在 `dist` 中分别双击：

- `start_account_A.bat`：使用默认数据目录，沿用原来保存的账号密码和处理记录。它与直接运行 EXE 属于同一个实例。
- `start_account_B.bat`：使用独立的 B 数据目录，首次填写第二个账号，之后独立记住密码。

更多账号可以复制 B 脚本并改名，例如 `start_account_C.bat`，每个脚本文件名对应一个独立数据目录。EXE 无需复制；启动脚本放在 EXE 同目录即可，也可直接使用项目根目录中的脚本启动 `dist` 下的 EXE。

A 的目录为 `%LOCALAPPDATA%\MailForwarderClient`；B 为 `%LOCALAPPDATA%\MailForwarderClient\instances\start_account_B`，C 依此类推。配置、密码、日志、实例锁和转发记录按目录隔离。新实例不会自动复制 A 的凭据或历史记录。

同一邮箱、同一转发通道配置在两个独立实例中时，会各自处理邮件，可能收到两次转发。

## 五个检测状态分别表示什么

| 状态 | 通过表示 | 失败时重点检查 |
| --- | --- | --- |
| 邮箱网络 | 可以连接指定服务器及 POP3 端口；所选 TLS 方式握手成功 | VPN、DNS、域名、端口、证书、网络策略 |
| 账号登录 | POP3 USER / PASS 验证成功 | 完整邮箱账号、密码 / 授权码、POP3 权限 |
| 邮箱读取 | 可以读取邮件数量和 UIDL 去重列表 | 服务器 POP3 能力、邮箱权限、UIDL 返回格式 |
| 企业微信通道 | HTTPS 请求成功，且响应 `errcode=0` | Webhook、机器人状态、企业微信返回码 |
| SMTP 邮箱通道 | SMTP 登录和测试邮件提交成功，收件地址未被拒绝 | SMTP 服务器、加密方式、授权码、收件地址 |

接口接受消息或 SMTP 接受邮件，不等于客户端能确认最终展示 / 投递到收件箱。最终收取请在群和邮箱确认，也要留意垃圾邮件目录。

邮箱读取成功且至少一个已启用通道检测成功时，可以开始转发；另一个异常通道会保留失败状态并重试。如果只启用的通道检测失败，需要先修正配置，或再次检测后再开始。

顶部状态栏显示最近一次检测 / 投递结果；底部显示本次统计和最近检查时间。「运行日志」页面查看具体结果。

## 配置与密码如何保存

- 默认数据目录：`%LOCALAPPDATA%\MailForwarderClient`，点击左下角「配置与日志目录」即可打开。
- `config.json` 保存服务器、账号、收件地址、通道开关等普通配置。
- 公司邮箱密码、SMTP 授权码和完整 Webhook 通过 Windows DPAPI 加密后保存；没有另存明文密钥。默认仅当前 Windows 用户在当前电脑上能解密。
- 复制 EXE 到别的电脑即可运行；复制配置文件后，旧凭据通常不能解密，需要重新输入并保存。
- 关闭「记住登录信息」开关后，再点击「保存配置」会移除之前保存的加密凭据；本次窗口仍可使用已输入的值，下次需重新输入。
- 非 Windows 环境可以用源码运行，但本版不持久保存密码、授权码或 Webhook。
- `delivery.sqlite3` 保存各账号、各通道的处理记录，不保存邮件正文；`forwarder.log` 记录运行结果，不记录密码或原邮件正文。
- `startup.log` 记录启动和界面异常。窗口无法打开时，按 Win+R 输入 `%LOCALAPPDATA%\MailForwarderClient`，可直接找到此文件。

## 与原脚本配置的对应关系

| 原脚本配置 | 客户端位置 |
| --- | --- |
| `CORP_POP3_HOST` / `CORP_POP3_PORT` | 邮箱账户 → POP3 服务器 / 端口 |
| `CORP_POP3_USE_SSL` | 邮箱账户 → 加密方式，另支持 STARTTLS |
| `CORP_EMAIL_USER` / `CORP_EMAIL_PASS` | 邮箱账户 → 邮箱账号 / 密码 |
| `ENABLE_WECOM_PUSH` | 转发通道 → 企业微信 → 启用 |
| `WECOM_WEBHOOK_URL` | 转发通道 → Webhook |
| `WECOM_MSG_TYPE` | 转发通道 → 消息格式 |
| 新增成员提醒 | 转发通道 → 提醒成员 UserID，Markdown / text 均支持 |
| `WECOM_MENTION_MOBILES` | 转发通道 → 提醒手机号（逗号分隔，支持 `@all`；仅 text 生效） |
| `ENABLE_QQ_MAIL_FORWARD` | 转发通道 → SMTP 邮箱 → 启用 |
| `QQ_SMTP_HOST` / `QQ_SMTP_PORT` | 转发通道 → SMTP 服务器 / 端口 |
| `QQ_EMAIL_USER` / `QQ_EMAIL_AUTH_CODE` | 转发通道 → 发件邮箱 / 授权码 |
| 原脚本发给自己 | 收件邮箱留空；也可填写另一个收件邮箱 |
| `POLL_INTERVAL_SECONDS` | 运行策略 → 检查间隔 |
| `NETWORK_TIMEOUT_SECONDS` | 运行策略 → 网络超时 |
| `TEST_LATEST_ON_FIRST_RUN` | 运行策略 → 首次测试最后一封 |
| `ONLY_FORWARD_KEYWORDS` | 运行策略 → 关键词过滤，留空则只按排除名单过滤 |
| 新增发件人排除 | 运行策略 → 发件人排除名单 → 排除发件邮箱 |

状态及日志路径由客户端管理，窗口显示运行日志；无需修改 Python 文件。

## 转发规则与原脚本中的问题修复

- 首次「开始转发」时建立历史基线；历史邮件不批量转发。若勾选首次测试，则列表最后一封进入正常处理流程，仍受排除名单和关键词过滤。
- 普通重启使用现有基线。更换公司邮箱后会建立该账号自己的基线，不会混用上一账号的邮件记录。
- 邮箱连接检测、通道测试、保存配置都不会提前把实际邮件标记为已处理。
- 每个通道成功后立即保存各自状态；某通道失败不会让其他成功通道重复投递，也不会阻塞后续邮件。
- 不再随机丢弃超过一万条的 UIDL 记录。状态文件损坏会报错，不会默默当作首次运行。
- 禁用的通道不安排历史补发；以后重新开启，仅处理尚未完成和之后的新邮件。更改收件地址 / Webhook 不会重发已完成邮件。
- 公司 POP3 默认验证 TLS 证书。使用公司自签名证书时，可选择 CA 文件；通常应使用 PEM 格式。也可以由使用者在界面明确取消证书校验。
- 企业微信正文按 UTF-8 字节截断，转发尝试之间预留至少 3.2 秒；多个客户端或其他程序共用机器人时，仍可能共同触发接口限流。
- QQ / SMTP 支持纯文本、HTML、正文内嵌图片和普通附件。单附件最多 10 MiB，总附件原始内容最多 16 MiB；超限附件会略过并注明。编码后整封转发邮件限 25 MiB。
- 验证码只在关键词附近识别 4–8 位数字，不再随意抓取全文任意四位或六位编号；提取只是辅助展示，不影响按关键词转发。
- 网络操作在工作线程中执行。停止会中断已登记的网络连接及轮询等待；遇到 DNS、建连等系统调用，停止可能仍需等其返回。关闭窗口有约 2 秒收尾上限，不再无限等待后台线程。
- 关闭窗口会停止转发；最小化窗口会继续运行。本版不包含系统托盘及开机自启动。
- 单个数据目录只允许运行一个实例，减少重复转发。

如果服务器已接受消息，但网络在返回成功响应之前断开，客户端无法确定实际投递结果，之后重试可能重复。这是邮件 / Webhook 端到端投递的固有限制；本地状态不能提供服务端幂等保证。

旧脚本的 `seen_uidls.json` 不会导入；新客户端在自己的数据目录建立独立基线。

## 验证与排错

在源码目录运行：

```powershell
py -3 -X utf8 -m unittest discover -s tests -v
py -3 -X utf8 check_startup.py --data-dir .build-smoke
py -3 -X utf8 check_startup.py --exe dist\MailForwarderClient.exe --data-dir .build-smoke-exe
```

第一条包含本地回环模拟 POP3 / SMTP / Webhook 的真实协议交互、服务器无响应时的取消、DNS 阻塞时的进程退出与锁释放、发件人排除及旧配置兼容测试，不会连接公司服务器或机器人。后两条分别检查源码和最终 EXE，只打开窗口并检查持续可见性，不发送网络请求；每次检查有 45 秒超时限制。失败时查看对应测试目录内的 `startup.log`。

常见问题：

- **旧版闪一下后消失、再次运行提示已在运行**：结束任务管理器中的旧进程，更新到本版后重新打包，确认打开的是新生成的 EXE。不要删除账号配置；单实例锁会随进程退出自动释放。
- **第 3 步测试失败，没有找到新 EXE**：流程尚未执行到第 5 步。独立窗口检查的失败详情会直接显示，并保留在 `.build-test-logs`；不能把测试窗口当作最终生成的 EXE。
- **新版仍无法启动**：查看 `%LOCALAPPDATA%\MailForwarderClient\startup.log`；打包检查失败则查看 `.build-smoke\startup.log` 或 `.build-smoke-exe\startup.log`。
- **网络红色、账号未检测**：优先确认 VPN、DNS 和端口。
- **网络绿色、账号红色**：服务器可达，重点核对密码、授权方式及 POP3 是否已启用。
- **TLS 证书错误**：核对服务器域名、系统时间，或选择公司 CA 证书。
- **检测通过，但首次测试未收到原邮件**：最后一封可能命中排除名单或未命中关键词；通道测试通知和真实邮件的首次测试是两件不同的事。
- **修改了配置**：先停止，修改后保存，再重新检测并开始。
- **开始后没有新邮件**：查看最近检查时间；默认只转发启动基线之后的新邮件，并按排除名单和关键词过滤。

构建错误保留在打包窗口中；启动和界面异常查看 `startup.log`，邮箱和转发错误查看 `forwarder.log`。打包时必须在目标 Windows 环境中执行，PyInstaller 不提供普通 Linux 到 Windows 的直接交叉打包。

实现参考：

- PyInstaller 官方文档：https://pyinstaller.org/en/stable/
- Microsoft DPAPI：https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata
- 企业微信消息推送配置：https://developer.work.weixin.qq.com/document/path/99110


## 源码界面依赖与打包资源

界面使用 CustomTkinter 5.2.2 和 Pillow，邮件连接、解析、加密保存和转发模块继续使用 Python 标准库。源码运行前可手动执行 `py -3 -m pip install -r requirements.txt`，也可使用自动处理依赖的 `run_windows.bat`。

Windows 打包脚本会收集 CustomTkinter 主题、字体和 darkdetect 资源，并在生成 EXE 后执行与正常启动路径一致的离线界面检查，核对实际可见性和检查结果文件。用户运行生成的 EXE 时不需要另装 Python 或界面库。
